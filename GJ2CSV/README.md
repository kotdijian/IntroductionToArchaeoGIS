# GeoJSON → CSV 変換ツール（GJ2CSV）

『考古学者のためのGIS入門：初級編』の実習用コードです。地理院地図の「作図・ファイル」から保存したGeoJSONを、Excelなどで属性を一覧・編集できるCSVへ変換します。**Python 3.9以上**で動作し、追加ライブラリのインストールは不要です。コードは本リポジトリの[MITライセンス](../LICENSE)で提供します。

## 準備と実行

Pythonの導入は[リポジトリのREADME](../README.md#pythonの導入とディレクトリ操作)を参照してください。

1. 地理院地図で「ツール」→「作図・ファイル」→「選択している情報をまとめて保存」から**GeoJSON形式**で保存します。
2. このフォルダに `inputGeoJSON` というフォルダを作り、保存した `.geojson` ファイルを入れます。`.json` の拡張子でも対応します。
3. ターミナル（macOS）またはPowerShell（Windows）を開き、この `GJ2CSV` フォルダへ移動します。

たとえば、リポジトリのフォルダに移動済みなら、次のコマンドを入力します。

```bash
cd GJ2CSV
```

現在の場所を確認するコマンドは両OSとも `pwd`、ファイルや配下のフォルダを確認するコマンドは `ls` です。一つ上のフォルダへ戻るときは `cd ..` を使います。別の場所から移動するときは `cd "/実際の保存場所/IntroductionToArchaeoGIS/GJ2CSV"` のように、実際のパスを指定します。Windowsでは `cd "C:\Users\名前\Documents\IntroductionToArchaeoGIS\GJ2CSV"` などです。例のパスは自分のパソコンに合わせて置き換えてください。

フォルダの配置例：

```text
GJ2CSV/
├── geojson_to_csv.py
├── README.md
├── inputGeoJSON/             ← 自分で作成する
│   └── tokyo_sites_edited.geojson
└── output/                   ← 実行時に自動作成される
    └── tokyo_sites_edited.csv
```

macOSでは次を実行します。

```bash
python3 geojson_to_csv.py
```

Windowsでは次を実行します。

```powershell
py -3 geojson_to_csv.py
```

本書の仮想環境を有効にしている場合は、どちらのOSでも `python geojson_to_csv.py` を使えます。`>>>` が表示されているPython対話モードではなく、ターミナル／PowerShellの通常の入力画面で実行してください。

**入力・出力の既定の場所は、スクリプトの置き場所ではなく、コマンドを実行した時の現在のフォルダが基準です。** `GJ2CSV` に移動してから実行すると、その中の `inputGeoJSON` を読み、`output` に保存します。入力フォルダ直下のファイルを一つずつ変換し、下位のフォルダは検索しません。元のGeoJSONは変更しません。

### ファイルや保存先を直接指定する

macOSの例：

```bash
python3 geojson_to_csv.py --input "inputGeoJSON/tokyo_sites_edited.geojson" --output "output/tokyo_sites_edited.csv"
```

Windowsの例：

```powershell
py -3 geojson_to_csv.py --input "inputGeoJSON\tokyo_sites_edited.geojson" --output "output\tokyo_sites_edited.csv"
```

入力フォルダ全体を変換する場合は、出力もフォルダとして指定します。

```bash
python3 geojson_to_csv.py --input "/実際の入力フォルダ" --output "/実際の出力フォルダ"
```

同名のCSVが既にある場合は停止します。別の保存先を選ぶか、必要な結果を退避してから再実行してください。意図的に上書きするときだけ `--overwrite` を付けます。

## 出力の内容

CSVの1行目は列名、2行目以降は1地物につき1行です。ファイル全体の属性を調べ、途中の地物にだけある属性も列に含めます。カンマ、引用符、改行を含む属性もCSVの規則に従って保存します。

元の属性列の後ろに次の列を追加します。

| 列 | 内容 |
| --- | --- |
| `lon` | Pointの経度。編集済みの図形の座標から取得します。 |
| `lat` | Pointの緯度。編集済みの図形の座標から取得します。 |
| `geometry_type` | Point、Polygonなど図形の種類。 |
| `geometry_geojson` | 元の図形をGeoJSONの文字列として保存。標高やポリゴンの頂点もこの列に残ります。 |
| `feature_id` | 地物の `id` がある場合に保存。 |

元の属性に `lon` や `lat` など上記と同名の列がある場合は、**元の属性を `property_lon` などに改名して残します**。その名前も既にある場合は `property_` をさらに付け、列名の衝突を避けます。改名内容は実行画面に表示されます。位置を変更したPointでは、元の属性に残った座標と図形の座標が異なることがあります。地理院地図へポイントとして読み込み直す際は、図形から取り出した **`lon` と `lat`** を選んでください。

Point以外のライン・ポリゴン・MultiPointなども属性を出力しますが、`lon`・`lat` は空欄になります。中心点などを勝手に作ることはしません。**このCSVを地理院地図へ読み込んでも、ポリゴンの範囲は復元されません。** 元のGeoJSONを保管し、図形の編集にはQGISなどを使います。CSVからGeoJSONへ戻す機能は含みません。

属性が配列やオブジェクトの場合は、JSONの文字列として一つのセルに保存します。空の属性や `null` は空欄となるため、CSVだけで元の型・空欄の意味を完全に復元することはできません。地理院地図が吹き出し内容を `description` などのHTML文字列にまとめている場合は、そのまま一つの列に保存します。HTML内の表から、元のCSVの列を自動復元する機能はありません。

GeoJSON標準のWGS 84の経度・緯度を前提とし、座標変換は行いません。別のCRSが明記されたファイルは停止します。QGISなどでEPSG:4326のGeoJSONへ変換してから使用してください。元データが標準と異なる座標を持つのにCRSが記載されていない場合、このツールだけでは判定できないため、提供元を確認します。

## Excelで開く・編集する

出力は**UTF-8（BOM付き）**です。日本語の文字化けを防ぎやすい形式ですが、コード・遺跡番号などの自動変換を防ぐため、ExcelではCSVを直接開かず、「データ」→「テキストまたはCSVから」などのインポート機能を使ってください。

- 文字コードはUTF-8、区切りはカンマを選び、プレビューを確認します。
- 遺跡ID・自治体コード・遺跡番号などを「テキスト」型として取り込み、先頭の0や長い番号、日付に似た値が変わらないようにします。
- 編集後は元のCSVを残し、別名で「CSV UTF-8」として保存します。Excelでの作業を続けるなら `.xlsx` も保存します。
- 地理院地図へ読み込み直すときは `lon` と `lat` を指定し、表示位置と吹き出しを確認します。属性名や吹き出しの表示方法は、地理院地図のCSV読込仕様に従います。

地理院地図で編集した吹き出しの表示情報が、そのまま元のCSVと同じ列になるとは限りません。元データ、変換したCSV、編集後のCSVを分けて保管してください。

## エラーが出たとき

入力の場所、ファイル名、拡張子を確認してください。JSONの構文が壊れている、Pointの座標が不正、既存の出力と名前が重複する場合などは、理由を表示して停止します。複数ファイルは事前に内容を検査しますが、書き込み中のディスク障害等では途中まで出力される場合があります。エラー後は保存済みファイルを確認してください。

作成したCSVや元のGeoJSONの公開・再配布は、利用したデータの提供条件に従ってください。コードのMITライセンスは、入力・出力データの利用条件を変更しません。
